> 对应课程第 3 天（9 月 9 日）核心产出
> 文档版本：V1.0 ｜ 编制日期：2026-09-09 ｜ 设计人：唐晶

## 1. 项目概况

"乌东文旅'衣食住行'综合服务平台"面向贵州黔东南乌东村文旅场景，为游客提供一站式线上服务（衣-非遗商品、食-餐饮美食、住-住宿预订、行-线路订票、社区-照片分享），为商家提供运营后台，为平台提供全局管理能力。

- 小组：乌东文旅开发小组（6 人），组内独立完成完整系统
- 技术栈：Midway 3（Node.js + TypeScript）+ Vue 3 + MySQL 8.0 + Redis 7 + Docker
- 架构形态：模块化单体（见 04-项目架构设计文档 ADR-1）

## 3. 技术实现亮点

1. **统一订单中心**：goods/meal/hotel/ticket/route 五类订单一条状态机（待支付→已支付→已确认→进行中→已完成，含取消/退款分支），各自扩展表承载差异化信息
2. **库存防超卖**：SKU/房态/票务/餐位全部采用条件 UPDATE（`WHERE stock >= n`）+ 超时订单关闭回补，测试覆盖预扣与回补全路径
3. **佣金与结算**：支付回调按订单类型区分佣金比例（实物 5% / 服务 10%，后台可配置），商家收入记账，T+7 结算自动生成并确认
4. **电子票核销**：路线/门票支付后按人数逐张生成电子票，核销校验"当日 + 未核销 + 未退款"三条件
5. **内容安全**：敏感词命中的发帖转人工审核（状态 0 待审），评论直接隐藏不计入展示数，管理员可过审/驳回
6. **配置外部化**：数据库/Redis/JWT 全部走环境变量，开发与容器部署同一套代码零改动
7. **AI 协作工程化**：项目级 Skill（wudong-dev 开发规范）、任务分解（19 项任务全程跟踪）、单元测试先行暴露真实缺陷

## 4. 测试与运行日志发现并修复的真实缺陷（价值证明）

| 缺陷 | 后果 | 修复 | 发现方式 |
| --- | --- | --- | --- |
| t_post.published_at 约束与审核流程冲突 | 敏感词发帖直接报数据库错误，功能不可用 | DDL 允许 NULL | 单元测试 |
| 路线下单误扣票务库存 | 路线购买必然失败 | 预扣分支按 bizType 区分 | 单元测试 |
| travel:routes 缓存 Key 缺 keyword 维度 | 关键词搜索与普通浏览互相命中缓存，列表串数据 | Key 增加 keyword 段 | 单元测试 |
| /api/cart/count 未登录崩溃 | 页面打开即报"系统繁忙"，用户误以为服务故障 | 控制器对空用户返回 0 | 运行日志巡检 |

前三个都是"演示必翻车"级的问题，被单元测试提前拦截；最后一个由运行日志巡检发现——服务本身正常但用户端持续报错，说明收尾阶段日志巡检与测试同等重要。

## 5. AI 协作方法总结（本组核心方法论）

本项目的实际开发由技术负责人 + Claude Code 完成，沉淀的方法：

1. **任务分解先行**：把 6 天课程拆成 19 个可验收任务（脚手架→模块→联调→缓存→测试→部署→文档→答辩），每项有明确完成标准
2. **规范 Skill 化**：把重复决策（命名/响应格式/鉴权/防超卖）固化为 `.claude/skills/wudong-dev`，AI 每次开发自动遵循，风格零漂移
3. **契约先行**：实体 + DDL + Swagger 注解三处同步，前后端按契约并行开发
4. **测试驱动收尾**：模块完成后统一补单元测试，不仅验证行为，还反向发现了三处业务缺陷
5. **证据留痕**：每个阶段产出文档（本 docs 目录），答辩材料与代码事实严格对应

## 6. 不足与改进方向

1. **admin 模块测试覆盖率 50.58%**：后台接口多而薄，部分列表/表单接口未逐条覆盖，后续可补充
2. **函数覆盖率 53.24%**：装饰器（@Auth 等）函数未被测试计数，属于统计口径问题，不影响核心逻辑验证
3. **CI 流水线尚未在 GitHub 实跑**：项目未推送远程仓库，流水线文件已交付并完成本地等效验证，推送后即可启用
4. **无小程序端**：需求书允许 PC Web 范围，若继续迭代可复用现有 API 开发小程序端
5. **支付为模拟方案**：受资质限制，接入真实支付需商户号与回调域名改造（回调接口已按真实结构设计）

## 7. 结论

项目在 3 个工作日内完成从需求拆解到可部署系统的全流程：6 大模块 + 公共能力全部实现，227 个测试用例全绿，Docker 一键部署验证通过，交付文档完整。通过 AI 协作 + 规范沉淀 + 测试兜底的方法，以小组规模完成了完整平台的开发与验证。
