> 对应课程第 3 天（9 月 9 日）核心产出

## 1. 测试方案

### 1.1 技术选型

| 项目 | 选择 | 说明 |
| --- | --- | --- |
| 测试框架 | Jest 29 + ts-jest | Midway 社区标准方案 |
| 数据库 | 真实 MySQL（wudong_test 独立测试库） | 不做 mock 数据库，保证 SQL 正确性；synchronize:false 使用真实表结构 |
| Redis | 内存版 FakeRedis | 测试聚焦业务逻辑，不依赖真实 Redis 进程 |
| 服务组装 | makeService 模式 | 直接 new 服务类 + 手动注入真实 Repository，避免容器启动开销 |
| 并行策略 | maxWorkers: 1 串行 | 测试文件共享同一测试库且逐用例清空，并行会互相污染 |

### 1.2 数据隔离

- 测试库 `wudong_test` 由 `scripts/prepare-test-db.js` 从 01-ddl.sql 生成（库名替换），本地与 CI 共用
- 每个用例执行前 `truncateAll()` 清空全部表（关闭外键检查并行 TRUNCATE），保证用例间互不影响
- 初始化脚本幂等，可重复执行

### 1.3 覆盖率门槛

- 目标：语句覆盖率 ≥ 60%（任务要求）
- 统计口径：`collectCoverageFrom` 覆盖 src 下全部业务代码（排除 entity/纯配置/纯 DTO 文件）

## 3. 发现并修复的真实缺陷

| 缺陷 | 发现方式 | 修复 |
| --- | --- | --- |
| t_post.published_at 在 DDL 中 NOT NULL，但敏感词审核路径写入 NULL | 测试执行时报数据库约束错误 | DDL 改为 `DATETIME DEFAULT NULL`，两库同步 ALTER |
| 路线下单必然失败：createOrder 对带 ticketOrder 参数的所有订单无条件预扣票务库存，路线订单用路线 ID 查票务库存必然落空 | 编写 buyRoute 成功路径用例时暴露 | 预扣分支增加 `bizType === 'ticket'` 判断，仅门票订单预扣 |
| travel:routes 缓存 Key 缺 keyword 维度：带关键词搜索与不带关键词浏览互相命中缓存，返回串数据 | 编写路线列表缓存用例时暴露 | Key 增加 keyword 段（四段 Key），并补隔离用例 |
| /api/cart/count 未登录（含 token 过期被守卫置空）时对 null 取 userId 抛 500，前端顶栏角标每次页面加载都会触发，页面反复报"系统繁忙" | 运行日志巡检（服务运行正常但用户端持续报错） | 控制器对空用户直接返回 0 |
| jest 多文件并行时互相清库导致假失败（12 个） | 全量执行时出现随机失败 | jest.config 设 maxWorkers: 1 串行 |

## 4. 结论

- 语句覆盖率 80.74%，超过 60% 目标要求
- 订单、支付、库存、退款、佣金等核心资金链路均有用例覆盖，且全部通过
- 全流程共发现并修复 4 个真实缺陷：3 个由测试暴露（DDL 约束、路线下单、缓存串数据），1 个由运行日志巡检发现（购物车计数接口未登录崩溃）
- 复现方式：`cd server && npm test`（报告输出于 server/coverage/）
