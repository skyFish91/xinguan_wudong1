# 答辩讲稿

> 对应课程第 3 天（9 月 9 日）核心产出
> 文档版本：V1.0 ｜ 编制日期：2026-09-09 ｜ 设计人：唐晶

## 1. 开场（约 30 秒）

各位老师好，我们是乌东文旅开发小组。我们的项目是"乌东文旅'衣食住行'综合服务平台"，面向贵州黔东南乌东村文旅场景，为游客提供衣、食、住、行、社区五位一体的一站式服务，同时为商家和平台提供运营管理能力。

系统采用模块化单体架构：后端 Midway 3 + TypeScript，前端两套 Vue 3 应用（游客 PC 端 + 管理后台），数据层 MySQL 8.0 + Redis 7，Docker Compose 一键部署。

## 2. 架构与模块（约 1 分钟）

项目的整体架构分四层：客户端层（PC 网页端、管理后台）、接入层（JWT 双 token 鉴权 + 统一响应格式）、业务层（六大模块 + 公共能力）、数据层（MySQL + Redis）。

六大模块分别是：衣——非遗商品、食——餐饮美食、住——住宿预订、行——线路订票、社区——照片分享、平台管理后台。公共能力包括用户体系、统一购物车、统一订单中心、模拟支付、文件上传、站内消息，由我们统一实现，六大模块共用。

架构上做了 10 条决策记录，关键的一条是：需求书里的微服务图是"建议"性质，我们评估 6 天课程周期后选择模块化单体——模块边界清晰、单体部署简单、保留了未来拆分微服务的可能。

## 3. 核心亮点（约 2 分钟，讲 3-4 个）

**第一，统一订单中心。** 五类订单（商品、餐位、住宿、门票、路线）共享一条状态机：待支付、已支付、已确认、进行中、已完成，加上取消和退款分支。每类订单用扩展表承载差异化信息，支付回调统一处理佣金记账——实物订单抽 5%、服务订单抽 10%，比例可以在后台配置。

**第二，库存防超卖。** SKU、房态、票务、餐位四类库存全部用条件 UPDATE 原子扣减，超卖直接失败；超时未支付的订单由定时任务关闭并回补库存。整条链路——预扣、回补、超卖拦截——都有单元测试覆盖。

**第三，内容安全。** 社区发帖经过敏感词过滤，命中的自动转人工审核；评论命中敏感词直接隐藏、不计入展示数。管理员可以过审或驳回。

**第四，测试与部署的工程化。** 227 个单元测试用例全部通过，语句覆盖率 80.74%，测试还帮我们发现并修复了三个真实缺陷。部署上，MySQL、Redis、后端、两个前端一共五个容器，一条命令拉起，健康检查和启动顺序都做了编排。CI/CD 流水线覆盖构建、测试和镜像验证。

## 4. AI 协作方法（约 1 分钟，本课程特色）

这个项目全程由 Claude Code 协作开发，我们沉淀了一套方法论：

第一，任务分解先行——把 6 天课程拆成 19 个可验收任务，逐项跟踪；第二，规范 Skill 化——把命名、响应格式、防超卖约定写成项目级 Skill，AI 每次开发自动加载，整个项目零风格漂移；第三，契约先行——实体、DDL、Swagger 注解三处同步；第四，测试兜底——单元测试不仅验证行为，还反向拦截了两个"演示必翻车"的缺陷。

我们的体会是：AI 把写代码的成本降下来之后，人的精力应该放在架构决策、需求确认和验收标准上——这些恰恰是 AI 替代不了的地方。

## 5. 演示引导（约 1 分钟）

接下来演示系统。我们会走一条完整的游客旅程：注册登录、浏览非遗商品、预订餐位和民宿、购买门票和路线、统一购物车结算、模拟支付、查看订单和电子票，最后切到管理后台看商家接单核销、平台数据看板和内容审核。

## 6. 常见问题预案（QA）

| 可能的问题 | 回答要点 |
| --- | --- |
| 为什么用模块化单体而不是微服务？ | 需求书微服务图为"建议"；6 天周期单体可交付可演示；模块边界已按微服务粒度划分，拆分路径保留（ADR-1） |
| 为什么支付是模拟的？ | 无商户资质；需求书允许模拟方案；回调接口按真实微信支付结构设计，接入真实支付只需替换回调来源 |
| 库存超卖怎么保证？ | 条件 UPDATE 原子扣减（WHERE stock >= n），MySQL 行锁保证并发安全；测试覆盖超卖与回补 |
| 测试覆盖率为什么选 60% 门槛？ | 任务要求为 60%，实际达到 80.74%；admin 模块接口薄且多，是主要拉低项 |
| JWT 怎么防止 token 泄露？ | access 2 小时短有效期 + refresh 7 天，前端拦截器自动续期；密码 bcrypt 存储；敏感信息展示脱敏 |
| 数据一致性如何保证（订单/库存/记账）？ | 同一事务内完成订单与库存扣减；支付回调幂等处理（已支付状态直接返回）；记账在回调内同步完成 |
| Docker 部署遇过什么问题？ | 基础镜像拉取受网络影响（VPN 劫持流量），断点续传重试解决；已记录进部署文档 |
| 小组怎么分工的？ | 一人主架构 + 全员模块协作：我负责公共能力与模块一，其余组员各负责一个模块，公共能力全员共用 |
