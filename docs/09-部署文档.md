## 1. 部署架构

五个容器单机编排（Docker Compose v2）：

```
浏览器 ──► nginx(web, 8081) ──┐
浏览器 ──► nginx(admin, 8082) ─┤ 反代 /api /uploads
                               ▼
                          server(7001) ──► mysql(3306) + redis(6379)
```

| 容器 | 镜像来源 | 对外端口 | 说明 |
| --- | --- | --- | --- |
| wudong-mysql | mysql:8.0 | 3306 | 首次启动自动执行 `sql/01-ddl.sql` + `sql/02-dml.sql`，数据卷持久化 |
| wudong-redis | redis:7-alpine | 不对外 | 热点缓存 + 验证码 + 首页聚合 |
| wudong-server | 构建（server/Dockerfile） | 7001 | Midway 后端，多阶段构建（编译 TS → 仅生产依赖运行） |
| wudong-web | 构建（web/Dockerfile） | 8081 | PC 端，Vite 构建产物由 nginx 托管并反代后端 |
| wudong-admin | 构建（admin/Dockerfile） | 8082 | 管理后台，同上 |

## 2. 关键设计

### 2.1 配置外部化

后端全部连接信息走环境变量（`server/src/config/config.default.ts`）：

| 环境变量 | 默认值 | 容器内取值 |
| --- | --- | --- |
| DB_HOST / DB_PORT / DB_USER / DB_PASSWORD / DB_NAME | 127.0.0.1 / 3306 / root / root / wudong | mysql 服务名直连 |
| REDIS_HOST / REDIS_PORT | 127.0.0.1 / 6379 | redis 服务名直连 |
| SERVER_PORT | 7001 | 7001 |
| JWT_SECRET / APP_KEYS | 开发默认值 | compose 注入 |

同一套代码开发环境与本机服务直连、容器环境走服务名，无需任何代码分支。

### 2.2 数据库初始化

MySQL 官方镜像约定：`/docker-entrypoint-initdb.d` 下的 `.sql` 文件在**数据卷首次创建**时按文件名顺序执行。将 `../sql` 目录只读挂载即完成建库建表 + 种子数据导入，无需手工执行脚本。

### 2.3 健康检查与启动顺序

- mysql / redis 配置 healthcheck（mysqladmin ping / redis-cli ping）
- server 使用 `depends_on: condition: service_healthy`，等数据库真正可用再启动，避免连接失败崩溃循环

### 2.4 前端静态托管与反代

前端构建产物是纯静态文件，由 nginx 托管，`/api` 与 `/uploads` 反代到 server 容器。前端代码只写相对路径 `/api`，开发（vite 代理）与生产（nginx 反代）零配置切换。

### 2.5 上传文件持久化

`server/uploads` 挂载命名卷 `uploads-data`，容器重建不丢失。

## 3. 部署步骤

### 3.1 一键部署（服务器）

```bash
cd deploy
cp .env.example .env     # 可选：修改密码与端口
docker compose up -d --build
```

或执行 `deploy/deploy.sh`（构建 + 启动 + 后端健康检查）。

### 3.3 团队本地开发

每位成员首次拉取代码后，在 `server` 目录复制环境变量模板，填写自己的数据库配置。不要提交 `.env` 文件：

```powershell
cd server
Copy-Item .env.example .env
# 编辑 .env，至少修改 DB_PASSWORD
npm install
npm run dev
```

数据库为空时，按顺序执行 `sql/01-ddl.sql` 和 `sql/02-dml.sql`。也可以在仓库根目录运行 `start-local.bat`，脚本会检查 `.env` 是否存在，并使用该文件启动后端。

### 3.2 验证

| 入口 | 地址 |
| --- | --- |
| PC 端 | http://<服务器IP>:8081 |
| 管理后台 | http://<服务器IP>:8082 |
| Swagger 接口文档 | http://<服务器IP>:7001/swagger-ui/index.html |

## 4. 常用运维命令

```bash
docker compose ps                 # 容器状态
docker compose logs -f server     # 跟踪后端日志
docker compose restart server     # 重启后端
docker compose down               # 停止（保留数据）
docker compose down -v            # 停止并清空数据（下次启动重新初始化库）
```

与同学联调访问时发现容器版存在两个开发版没有的问题，均已修复并验证：

| 缺陷 | 现象 | 根因 | 修复 |
| --- | --- | --- | --- |
| 种子数据中文乱码 | 8081 页面中文全部显示为 `ä¹Œä¸œè‹—å¯¨` 式乱码（本机 5173 开发版正常，因其连本机 MySQL） | mysql 官方镜像执行 docker-entrypoint-initdb.d 时导入连接字符集为 latin1，UTF-8 的 SQL 文件被双重编码写入 | `sql/01-ddl.sql` 与 `sql/02-dml.sql` 开头增加 `SET NAMES utf8mb4;`，重建数据卷后重新导入 |
| 种子图片 404 | 首页轮播等占位图全部不显示，`/uploads/seeds/*.svg` 返回 404 | `server/.dockerignore` 排除了整个 uploads 目录，种子 SVG 从未进入镜像；uploads-data 卷挂载后容器内无 seeds | `.dockerignore` 改为仅排除运行时目录（`uploads/tmp`、`uploads/2026*`）；Dockerfile 增加 `COPY uploads/seeds ./uploads/seeds`，卷首次挂载自动复制 |

## 6. 与架构文档的差异说明

04-项目架构设计文档 ADR-9 原定"MySQL 用本机服务，应用 + Redis 容器化"；实际实现时全量容器化（MySQL/Redis 都进 compose），理由：

- 一键部署：新机器 clone 仓库 + 一条命令即可跑通全部环境
- 与课程答辩演示场景匹配（环境可迁移、可重复）
- 数据卷保证数据持久化，与本机服务无本质差异
