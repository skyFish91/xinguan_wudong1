# 项目分组方案与模块认领

> 对应课程第 1 天（9 月 7 日）核心产出：项目分组方案、模块认领、AI 开发环境检查表
> 文档版本：V1.0 ｜ 编制日期：2026-09-08

## 1. 项目分组方案

### 1.1 小组概况

| 项目 | 内容 |
|------|------|
| 小组名称 | 乌东文旅开发小组（本组） |
| 小组人数 | 6 人 |
| 项目名称 | 乌东文旅"衣食住行"综合服务平台 |
| 项目范围 | 全部 6 个模块 + 公共能力（需求书要求每组独立完成完整系统） |
| 终端范围 | PC 网页端 + 管理后台（Web） |
| 实施方式 | 6 个学生小组独立开发完整系统，组内自行分工 |

### 1.2 组织方式（需求书约定）

《乌东文旅"衣食住行"综合服务平台需求规格说明书 V2.0》明确：

- **每个小组独立完成完整系统**，包含全部 6 个模块
- **组内自行分工**，可按模块、功能或技术层次划分
- **独立数据库**，每组使用独立的数据库实例
- **独立部署**，每组系统可独立运行和演示

### 1.3 本组实施策略

本组采用"**一人主架构 + 全员模块化协作**"策略：

| 角色 | 职责 |
|------|------|
| 技术负责人（唐晶） | 系统架构设计、脚手架搭建、公共能力实现、技术方案统一、文档汇总 |
| 组员（按模块分工） | 各模块页面与接口开发、测试用例、联调 |

组内每人负责一个模块的开发任务，公共能力（用户体系、购物车、订单、支付、上传、消息）由技术负责人统一实现，全员共用。

## 3. 协作规范

### 3.1 Git 规范

- 主分支 `main`，功能分支 `feature/模块名`
- 提交信息格式：`[模块] 简要说明`，如 `[衣] 商品列表接口`
- 每天课程结束前合并当日成果并打 tag

### 3.2 代码规范

- 后端：TypeScript + Midway 装饰器风格，Controller → Service → Entity 三层
- 前端：Vue 3 组合式 API + Element Plus，页面按模块目录划分
- 命名：数据库表 `t_` 前缀，API 路由 `/api/模块/资源`

### 3.3 每日站会

- 每节课前 5 分钟同步进度与阻塞
- 接口契约先行，前后端按 Swagger 文档对齐
